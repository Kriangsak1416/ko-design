# Liquid Glass

มาตรฐานหน้าตาและการตอบสนองสำหรับเว็บที่เลือกใช้ดีไซน์ Liquid Glass เอกสารนี้ใช้ได้โดยไม่ต้องเปิดโค้ดของเว็บอื่น ส่วนค่าที่ต้องเหมือนกันทุกเว็บมีโค้ดให้คัดลอก

ถ้าเว็บใดต้องการค่าที่ต่างจากนี้ ให้แก้เอกสารนี้ก่อน แล้วจึงนำไปใช้ เพื่อให้ทุกเว็บที่ใช้ดีไซน์นี้ยังอ้างอิงจากที่เดียว

## หลักการ

หน้าเว็บเป็นแผ่นกระจกโปร่งแสงลอยเหนือภาพพื้นสีสด แนวเดียวกับ iPhone Liquid Glass โดยยึด 4 ข้อนี้:

1. **ตอบสนองทันที** ทุกการกดต้องเห็นผลในเฟรมแรก แม้ server ยังไม่ตอบ
2. **ลื่นไหล** การเปลี่ยนหน้าต้องบอกได้ว่าอะไรกลายเป็นอะไร
3. **อ่านง่ายก่อนสวย** กระจกต้องไม่ทำให้ข้อความอ่านยาก
4. **มีชิ้นเด่นชิ้นเดียว** แต่ละหน้าเลือกสิ่งที่ผู้ใช้ต้องมั่นใจมากที่สุดให้เป็นชิ้นเด่น ส่วนอื่นให้นิ่ง

## ข้อห้าม

ต้องทำตามหัวข้อ "ข้อห้ามของทุกดีไซน์" ใน `SKILL.md` ของ skill นี้ และมีข้อห้ามเฉพาะ Liquid Glass ดังนี้

- ห้ามวางข้อความบนภาพพื้นโดยตรงถ้าเป็นข้อความยาว ให้วางบนกระจกหนา

## เริ่มใช้กับเว็บใหม่

1. คัดลอกไฟล์ฟอนต์และไฟล์ไลเซนส์จาก `fonts/` ในโฟลเดอร์ของดีไซน์นี้ ไปไว้ในโฟลเดอร์ `fonts/` ข้างไฟล์ CSS ของเว็บใหม่
2. คัดลอกโค้ดจากหัวข้อ "ตัวอักษร" "สี" "ภาพพื้น" และ "กระจก" ไปไว้ต้น CSS
3. เลือกชิ้นเด่นของแต่ละหน้า และกำหนดว่าจะแปลงร่างข้ามหน้าไปเป็นอะไร
4. ทำสถานะรอตามหัวข้อ "สถานะรอ server"
5. ตรวจตามหัวข้อ "ตรวจก่อนส่งมอบ"

ชื่อคลาส `.glass-clear` และ `.glass-thick` ในเอกสารนี้เป็นชื่อแนะนำ ถ้าเว็บใช้ framework ให้นำตัวแปรเหล่านี้ไปผูกกับ theme ของ framework และห้ามตั้งค่าสีใหม่

### ค่าความต่างของสี

เกณฑ์ WCAG AA คือข้อความปกติอย่างน้อย 4.5:1 และขอบของส่วนควบคุมอย่างน้อย 3:1 ตารางนี้คำนวณจากกรณีแย่ที่สุด คือกระจกวางบนสีเข้มที่สุดของภาพพื้น ค่าจริงเปลี่ยนตามความเบลอและความอิ่มสีของกระจกได้เล็กน้อย

| สี | ใช้กับ | บนกระจกหนา | บนกระจกใส |
| --- | --- | --- | --- |
| `--ink` | ข้อความหลัก | 14.43 | 11.70 |
| `--muted` | ข้อความรอง | 7.74 | 6.28 |
| `--blue-deep` | ลิงก์ | 8.10 | 6.57 |
| `--blue` | ขอบ focus, พื้นปุ่มหลัก | 5.07 | **4.12** ห้ามใช้เป็นสีข้อความ |
| `--ok` | สำเร็จ | 5.62 | 4.56 |
| `--err` | ผิดพลาด | 5.86 | 4.75 |
| `--warn` | แจ้งเตือน | 5.77 | 4.68 |
| `--line` | ขอบช่องกรอก | 3.52 | **2.86** ห้ามใช้เป็นขอบส่วนควบคุม |

ข้อความขาวบนปุ่มหลักได้ 4.74 ที่ขอบบน และ 5.98 ที่ขอบล่าง

## ส่วนประกอบ

### ปุ่ม

กดแล้วยุบทันที ปล่อยแล้วเด้งกลับ ปุ่มสูง 46px ปุ่มเล็กในแถบนำทางสูง 36px และบนมือถือต้องสูงอย่างน้อย 44px

```css
button {
  position: relative;
  min-height: 46px;
  padding: 9px 26px;
  border: 0;
  border-radius: 999px;
  background: linear-gradient(180deg, #0A6FE6, var(--blue));
  box-shadow: inset 0 1px 0 rgba(255, 255, 255, .4), 0 6px 18px rgba(0, 95, 204, .32);
  color: #fff;
  font: inherit;
  font-weight: 600;
  cursor: pointer;
  transition: transform .45s var(--spring), filter .1s;
}
button:hover { filter: brightness(.92); }
button:active { transform: scale(.95); filter: brightness(.86); transition-duration: 40ms; }
```

ปุ่มรองใช้กระจกใสและสี `--ink` น้ำหนัก 500 แต่ละแผงควรมีปุ่มหลักสีน้ำเงินปุ่มเดียว

### ช่องกรอก

- พื้นขาว 80% ขอบ `--line` และใช้ `font: inherit`
- เมื่อ focus ขอบเป็น `--blue` พร้อมวง `box-shadow: 0 0 0 4px rgba(0, 95, 204, .25)`
- วางบนกระจกหนาเท่านั้น เพราะ `--line` บนกระจกใสไม่ถึงเกณฑ์
- ช่องที่รับรหัสหรือเลขที่ต้องตรวจทีละตัวใช้ `--mono`

### แถบนำทาง

ลอยแบบ `position: sticky` เหนือเนื้อหาด้วยกระจกใส ซ้ายเป็นชื่อระบบ ขวาเป็นผู้ใช้และปุ่มออกจากระบบ บนมือถือเปลี่ยนเป็น `position: static` เพื่อไม่ให้บังเนื้อหา

### ข้อความแจ้ง

| คลาส | พื้น | สีข้อความ | ใช้เมื่อ |
| --- | --- | --- | --- |
| `.msg.ok` | `rgba(226, 248, 234, .9)` | `--ok` | ทำสำเร็จ |
| `.msg.info` | `rgba(255, 246, 219, .92)` | `--warn` | ไม่ใช่ความผิดของผู้ใช้ และไม่มีอะไรเสียหาย เช่น หน้าหมดอายุ |
| `.msg.err` | `rgba(255, 232, 229, .92)` | `--err` | ทำไม่สำเร็จ หรือกรอกข้อมูลไม่ถูกต้อง |

ใช้ `role="status"` กับข้อความสำเร็จและข้อความแจ้ง ส่วนข้อผิดพลาดใช้ `role="alert"`

### รายการผลลัพธ์

ใช้แบบหน้า Settings ของ iPhone บนกระจกหนา คั่นแถวด้วยเส้น `--hair` และมีวงสถานะขนาด 24px หน้าแถวเสมอ

| สถานะ | สัญลักษณ์ | สี |
| --- | --- | --- |
| สำเร็จ | ✓ | `--ok` |
| ไม่สำเร็จ | ! | `--err` |
| ไม่มีข้อมูล | วงว่าง | `--line` |

### หน้าเข้าสู่ระบบ

ชื่อระบบอยู่กลางจอ และมีแผ่นกระจกหนากว้างไม่เกิน 440px ปุ่มเข้าสู่ระบบเต็มความกว้างแผ่น

## การเคลื่อนไหว

ใช้การเคลื่อนไหวเพื่อตอบการกระทำของผู้ใช้เท่านั้น ห้ามเล่นเองเพื่อตกแต่ง

| จังหวะ | ค่า |
| --- | --- |
| กดปุ่ม | ยุบเหลือ 95% ใน 40ms |
| ปล่อยปุ่ม | เด้งกลับ .45s ด้วย `--spring` |
| วง focus | .35s ด้วย `--spring` |
| ชิ้นเด่นแปลงร่างข้ามหน้า | .28s `cubic-bezier(.2, .9, .25, 1)` |
| เนื้อหาเข้าหน้า | เฟดและขยับ 6px ใน .2s |
| วงสถานะในรายการ | เด้งเข้า .4s ห่างกันแถวละ .08s |

### การเปลี่ยนหน้า

เว็บหลายหน้าทำได้ด้วย CSS ล้วน:

```css
@view-transition { navigation: auto; }
@media (scripting: none) { @view-transition { navigation: none; } }
:root { view-transition-name: none; }
::view-transition { pointer-events: none; }
::view-transition-group(subject) { animation-duration: .28s; animation-timing-function: cubic-bezier(.2, .9, .25, 1); }
::view-transition-old(subject), ::view-transition-new(subject) { height: 100%; animation-duration: .16s; }
```

ใส่ `view-transition-name: subject` ให้ชิ้นเด่นของแต่ละหน้า หน้าละ 1 ชิ้น แล้วปฏิบัติตามนี้:

- **ห้ามจับภาพทั้งหน้า** ระหว่างเล่น เบราว์เซอร์จะทิ้งการกดบนส่วนที่ถูกจับภาพ และ `pointer-events: none` แก้ไม่ได้
- ชิ้นที่ถูกจับภาพจะกดไม่ติดราว .28 วินาที ถ้ามีปุ่มอยู่ในชิ้นนั้น ต้องให้กด Enter ในช่องกรอกแทนได้
- ต้องปิด transition เมื่อปิด JavaScript ตามโค้ดด้านบน ไม่เช่นนั้นกดปุ่มไม่ได้
- ส่วนอื่นให้สลับทันทีแล้วค่อยเฟดเข้า เพื่อให้กดได้ตั้งแต่เฟรมแรก

### ลดการเคลื่อนไหว

```css
@media (prefers-reduced-motion: reduce) {
  @view-transition { navigation: none; }
  *, *::before, *::after { animation: none !important; transition: none !important; }
  button:active { transform: none; }
}
```

ถ้าเว็บใช้วงกลมหมุน ต้องคงการหมุนไว้ เพราะเป็นสัญญาณเดียวว่ากำลังรอ

## สถานะรอ server

| สถานการณ์ | สิ่งที่แสดง |
| --- | --- |
| รู้โครงหน้าถัดไป เช่น ค้นหาหรือบันทึก | ภาพโครงของหน้าถัดไป (Skeleton) |
| ไม่รู้ผล เช่น เข้าหรือออกจากระบบ | วงกลมหมุนในปุ่ม |

- แสดงหลังรอ 500ms เพื่อไม่ให้กะพริบ ค่านี้วัดจากเว็บตัวอย่าง ซึ่งเปลี่ยนหน้าค่ากลางราว 265ms เว็บที่ช้ากว่านี้มากควรวัดแล้วปรับ
- ปิด JavaScript แล้วฟอร์มต้องยังทำงานได้ สถานะรอเป็นเพียงส่วนเสริม
- ภาพโครงต้องมี `aria-hidden="true"` และฟอร์มที่กำลังส่งต้องมี `aria-busy="true"`
- เมื่อกลับด้วยปุ่มย้อนกลับ ต้องล้างสถานะรอทั้งหมดใน `pageshow`
- ภาพโครงควรมีชิ้น `view-transition-name: subject` เพื่อแปลงร่างเป็นชิ้นจริงตอนหน้าใหม่มาถึง

## การเขียนข้อความ

- เขียนจากมุมของผู้ใช้ ไม่ใช้ชื่อตารางหรือศัพท์ของระบบ
- ปุ่มบอกสิ่งที่จะเกิดขึ้น เช่น "บันทึกรหัสผ่านใหม่" ไม่ใช้ "ตกลง"
- ข้อความแจ้งต้องบอกว่าเกิดอะไรขึ้น รายการถูกบันทึกหรือยัง และต้องทำอะไรต่อ เช่น "หน้านี้หมดอายุแล้ว รายการยังไม่ถูกบันทึก กรุณาทำอีกครั้ง"
- หน้าระบบขัดข้องต้องไม่แสดงรายละเอียดทางเทคนิค

## ข้อกำหนดทางเทคนิค

- ดีไซน์นี้ทำงานได้ภายใต้ CSP แบบ `script-src 'self'; style-src 'self'; font-src 'self'` จึงไม่ควรใช้ inline script หรือ inline style
- ก่อนตั้งแคชถาวรให้ CSS และ JS ต้องมี version ใน URL เช่น `?v=` จาก hash ของไฟล์
- ถ้าเบราว์เซอร์ไม่รองรับ `linear()` หรือ View Transition หน้าเว็บต้องยังใช้งานได้ โดยเปลี่ยนหน้าตามปกติ

## ขอบเขตที่ยังไม่ครอบคลุม

ส่วนนี้ยังไม่เคยทำจริง จึงยังไม่มีมาตรฐาน เมื่อเว็บแรกต้องใช้ ให้ออกแบบโดยยึดหลักการด้านบน แล้วเพิ่มกลับมาในเอกสารนี้

- ตารางข้อมูลขนาดใหญ่ และกราฟ
- หน้าต่างซ้อน (modal) และเมนูแบบเลื่อนลง
- โหมดมืด ตอนนี้กำหนด `color-scheme: light` เท่านั้น
- แอปหน้าเดียว (SPA) โค้ดเปลี่ยนหน้าในเอกสารนี้ใช้กับเว็บหลายหน้า แอปหน้าเดียวต้องเรียก View Transition ผ่าน JavaScript หรือ framework และยังไม่ได้ทดสอบ
- เบราว์เซอร์อื่น การทดสอบจริงทำบน Microsoft Edge เท่านั้น ยังไม่ได้ทดสอบบน Safari, Firefox และเครื่องมือถือจริง

## ตัวอย่างอ้างอิง

`example/index.html` ในโฟลเดอร์ของดีไซน์นี้เป็นหน้าตัวอย่างที่เปิดดูได้ทันที ใช้ HTML และ CSS ล้วน ข้อมูลทั้งหมดเป็นข้อมูลสมมติ ไม่มีวงกลมหมุนและภาพโครง

เว็บ person-password เป็นตัวอย่างแรกที่ใช้ดีไซน์นี้ เป็นเว็บ PHP แบบหลายหน้าที่ไม่ใช้ framework ไฟล์ด้านล่างอยู่นอก skill นี้ จึงอาจไม่มีในบางเครื่อง ถ้าไม่พบให้ยึดเอกสารนี้

| ไฟล์ใน `D:\My windows app\person-password\` | ดูเรื่อง |
| --- | --- |
| `public/style.css` | ส่วนประกอบครบ รวมวงกลมหมุนและภาพโครง |
| `public/app.js` | การสร้างภาพโครงและล้างสถานะรอ |
| `src/app.php` (`send_headers`, `asset`, `page_open`) | CSP, version ของไฟล์ และการ preload ฟอนต์ |
| `Dockerfile` | การตั้งแคชถาวรให้ `.woff2`, `.css`, `.js` |

ในเว็บนี้ ชิ้นเด่นคือบัตรของคนที่กำลังจะเปลี่ยนรหัส เพราะงานหลักคือมั่นใจว่าเปลี่ยนให้ถูกคน แถบค้นหาจึงแปลงร่างเป็นบัตรเมื่อค้นเจอ
